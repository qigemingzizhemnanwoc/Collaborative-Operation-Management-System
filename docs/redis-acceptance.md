# Redis 防重复提交验收

2026-11-05：第三项限定范围本地验收通过。不进入Docker。此结论不包含跨实例故障切换严格幂等或生产上线验收。

## 原有与二次开发
原项目已有 Spring AOP @Before、Redis SET NX+TTL、本地Map降级。本次改进：JSON数组及SHA-256参数指纹，完整身份/方法/路径再次哈希；保留null及参数边界、Map排序；直接文件参数仅使用元数据；本地按独立绝对到期时间清理，容量10000硬限制，检查与插入同步执行；非正TTL拒绝。没有新增缓存框架、分布式锁或业务缓存。
核心代码：PreventDuplicateSubmitAspect.java；测试：RedisDuplicateIntegrationTest.java。未修改库存与员工业务规则。

## 最终统一结果
40项通过，失败0、错误0、跳过0：Redis7、员工17、库存16。公开版只保留 docs/verification/deployment/junit-summary.json 安全摘要。此前批次不重复累计。首轮真实断连测试因驱动实际抛RedisSystemException而非预期子类失败，调整为DataAccessException契约后最终重跑通过。

## 可信证据
- 127.0.0.1:16379独立Redis：真实AOP目标执行计数验证首次、重复、TTL、参数隔离及8线程竞争。
- 真实Sa-Token会话验证同用户重复拒绝、不同用户和路径独立；不是密码登录端到端测试。
- 本地混合过期/容量测试；9995条预置有效记录，16线程争抢5个槽位，恰好5次业务执行、最终10000条。满容量拒绝，不放行；过期项释放槽位。
- 真实断连恢复：测试通过ProcessBuilder在随机空闲本机端口创建自己的Redis进程，持有Process对象，只终止该对象并等待退出，再在同端口重建。没有停止已有16379或其他服务，没有FLUSH。
- 联合测试通过真实AOP代理+Spring TransactionTemplate+隔离MySQL sys_user表。Redis正常拒绝重复；自建Redis退出后PING真实失败，切面降级；用户写入后注入异常，事务回滚、无用户残留；立即重试被本地标记拒绝。恢复后本地标记未同步到Redis，额外一次请求到达数据库，被用户名唯一约束拒绝，记录仍只有一条；再次请求由Redis拒绝。
- 联合测试是基于现有账号表与事务组件的最小测试业务，并非完整员工Controller联合链路；真实员工/库存Service回滚与并发由其17/16项回归覆盖。

## 已知边界和策略
1. 故障/恢复切换窗口不连续：Redis和本地标记不互相复制，可能额外放行。不能依赖防重保证库存操作只发生一次；既有条件扣减、状态转换、唯一索引、事务仍必须保留。新建不同业务单号仍不具备持久请求幂等。
2. 本地降级仅当前实例有效；多实例无法统一防重。数据库是业务一致性边界。
3. 失败请求仍占用窗口，用户需等TTL再重试。事务回滚不等于删除Redis标记。
4. 容量最多10000条；空闲或Redis恢复后不会自动主动清扫本地Map，但仍有硬上限，下次降级会清理过期项。每次降级扫描有成本，未做性能基准。
5. 文件只取元数据，不读内容；相同元数据不同内容可能误判。现有上传接口未使用防重注解。任意复杂对象/嵌套文件不承诺全面兼容。哈希不是加密，不承诺防字典猜测。
6. 测试自建Redis已由finally清理；之前独立16379测试实例保留。Windows Redis路径写在测试辅助方法中，跨机器运行需配置现有可执行文件路径，尚未容器化。
